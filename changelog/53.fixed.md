The Collector no longer mis-keys multi-path gNMI GET responses. `gnmi_get` now fetches each requested path individually (within one connection) and stamps every empty-path update with its requested path before merging, so a device that returns notifications out of order — or in a different count than requested — can't have its data attributed to the wrong path. Removes the fragile position-based path recovery that could silently swap or drop verification data (e.g. interface vs. BGP subtrees on the deploy verify step).

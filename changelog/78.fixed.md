Loopback intent is now renderable on SR Linux: seeds name the loopback `lo0` (was the invalid `loopback0`), `mtu` is optional end to end (model, SoT schema, template) so loopbacks carry none, and the executor no longer injects a synthetic `lo0` from `system.j2` — the seeded loopback with its router-id address is the loopback. Environments seeded before this fix must delete the stale `loopback0` rows and reseed.

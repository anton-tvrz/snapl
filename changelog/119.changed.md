Workflows no longer name a vendor. `DeployIntent` and `ScanDrift` used to import the SR Linux `DRIFT_PATHS` and pass them into a generic `collect_running_state(device, paths)` activity. They now call `collect_drift_state(device)`, which resolves the paths from the collect adapter next to `detect_drift`, which already applies the SR Linux normalization. The activity layer is now the single seam between the workflows and the vendor shape of the data, as constitution Principle VI requires, and a unit test fails if any workflow imports a vendor seam module again. The audit trail records the new activity name. Drain the worker before upgrading: a workflow already in flight scheduled the old activity name and will fail replay.

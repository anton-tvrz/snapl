An extra IPv4 address on an interface that intent manages is now reported as undesired config, under its own path (`/interface[name=…]/subinterface[index=…]/ipv4/address[ip-prefix=…]`). Before, the scan compared only the first address the device listed, so a hand-added address was either invisible or, when the device listed it first, made the intended address read as wrong. Not yet checked against the live lab.

Deploy and reconcile no longer fail forever on a device that carries config intent never asked for. Post-apply verification runs the same drift diff as a scan, and since #114 that diff reports undesired config, which apply cannot remove (#65). So one hand-added interface description made every deploy and reconcile of that device end in `verification_failed`, even when the apply had fixed everything it was asked to. Verification now judges the change just applied: it fails only on forward drift. Undesired config is still reported, as constitution VIII.5 requires: the deploy result says how many paths not in intent remain, the audit trail records them as `undesired_paths` on the workflow's termination, and `snapl scan` continues to flag them. A report mixing forward and undesired drift still fails, and carries both.

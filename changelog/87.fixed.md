`provision_schema` now blocks until Infrahub has finished registering the schema before returning, so a following `seed` on a fresh instance no longer races the async schema apply and silently drops unknown attributes (e.g. `use_case`/`lab_node_name` on `DcimDevice`). The loader polls `schema.all(refresh=True)` until every extension attribute it just loaded is visible, bounded by a timeout that raises a clear `IntentSchemaError`.

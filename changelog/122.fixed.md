A device-default MTU no longer reads as hand-added config, and the lab no longer floats on `srlinux:latest`. On SR Linux v26.3.1 a port given only a description by hand reports `mtu 9232`, its default, so a scan showed two undesired items where the operator had added one. The drift field map now lists `device_defaults` (`mtu: 9232` for interfaces): a value equal to the device default neither marks a port as configured nor appears as an undesired item, while a hand-set non-default MTU still does. Desired MTUs are still compared strictly. The cause of the surprise was the image: `containerlab/dcfabric.yml` used `ghcr.io/nokia/srlinux:latest`, which had moved from the August build to v26.3.1 with no change in this repo, and has since moved again. It is now pinned to `26.3.1`, and a test fails if it goes back to `latest`. A real v26.3.1 payload is kept as a fixture.

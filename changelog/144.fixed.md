A scheduled remediate run that hits its 30-minute timeout no longer kills the repair it started. The reconcile child is now abandoned rather than terminated when its parent run closes, so a `DeployIntent` cut off between apply and verify still verifies (and rolls back if it must), and the reconcile and its deploys write their own audit records. A later scheduled run that finds the same device still drifted skips it while that deploy is in flight. Runs already in progress when this ships keep the old behaviour (patched for replay safety).

An interface in `provisioning`, `maintenance` or `outage` is now rendered admin-enabled. Both mappers derived enablement as `status == "active"`, so a link being brought up — exactly when its config is first pushed — was rendered admin-shutdown, and the observer flagged the live-up port as drift. One shared rule now covers interfaces and BGP sessions: `active`, `provisioning`, `maintenance`, `outage` and no status are enabled; `free`, `disabled` and `deleted` are disabled, and any unrecognised value stays disabled as before. BGP sessions (`active`/`disabled`/`deleted`) map exactly as they did. A unit test reads the packaged schema and fails if a status choice is added without being classified.

snapl's dev stack no longer binds any conventional default port. Infrahub 8000, Temporal 7233, Neo4j 7474/7687, Redis 6379, RabbitMQ 5672/15672, Prefect 4200 and the Temporal Web UI 8233 are all claimed by sibling projects on a shared developer machine — aiming at one of them reached another project's Infrahub and attempted to load snapl's schema into it. snapl now owns the contiguous 18000-18099 block (Infrahub 18000, Temporal 18033, Web UI 18034, …), recorded together with the containerlab subnet registry in `dev/knowledge/host-resource-registry.md`. A `+1` offset was not a fix: 8001 belongs to another project too. Separately, `demo.check`, `snapl status` and the end-to-end suite now verify the Source of Truth's *identity* rather than only its reachability — an Infrahub holding devices but lacking snapl's `use_case` attribute is reported as another project's, and the e2e suite refuses to seed into it.

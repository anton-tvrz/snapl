A device whose deploy is already in flight no longer kills the whole reconcile batch. `ReconcileDevicesWorkflow` starts children with the same `deploy-intent-<id>` id family the operator entry point uses, so an operator-started deploy running at the same time raised `WorkflowAlreadyStartedError` past the `ChildWorkflowError` handler and failed every other device's reconcile with it. That collision is now caught and counted as a skip — reconcile's goal for that device is already being met — and the remaining devices reconcile normally.

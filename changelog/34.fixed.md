A retried audit write no longer fails the workflow it belongs to. Temporal retries `record_audit_event` with the same event when an attempt times out or the worker dies after the row was committed, and `SqliteAuditLog` refused the duplicate `event_id`. Every retry failed the same way, so a deploy, scan, reconcile or scheduled run failed even though its record was saved. Appending an event that is already stored is now a no-op in both audit backends.

Interfaces and BGP sessions no longer vanish from desired state when their `device` relation won't resolve. `get_desired_state` grouped each child onto its device by resolving the child's `device` peer, and the live SDK's `.peer` raises when that peer misses the SDK store; the error was swallowed and the child dropped without a word, so the observer read real config as live-only drift and reconcile could remove it — the empty-intent symptom of #33 by another route. Children are now attributed by the query that returned them: with one device queried, every child is that device's, and across several devices the relation's own id, which the SDK fills from the query response without a store lookup, picks the parent. A child that still names no queried device is logged as a warning with a count instead of disappearing silently, and the mappers' unreachable `fallback_device_id` branch is gone: they take the device the child was grouped under.

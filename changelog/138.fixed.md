Scheduled drift runs can no longer silently stop the schedule, mislabel a failed repair, or report a cancelled scan as clean. Every scheduled run now times out after 30 minutes, so one that never finishes no longer holds the SKIP overlap slot and blocks every later scan. Existing schedules get the timeout at the next `snapl schedule create` or `invoke demo.up`, or at a mode switch. When a remediate run's reconcile fails as a whole, the run records `remediation_failed` instead of blaming the Source of Truth, and still writes a `DRIFT_RESPONSE` record for every device it decided about, with `result: "unknown"` for devices whose deploys may already have written. A scan cancelled on its own (rather than through its run) fails the run instead of counting as a successful scan of zero devices; `DriftScanResult` gains a `cancelled` flag. A device listed twice in a use case no longer breaks the scan. `snapl schedule trigger` refuses while a run is in progress instead of recording a run that never starts. A schedule whose interval was replaced outside snapl gives a one-line error naming the fix instead of a traceback. A mode switch decides against the schedule it updates. The audit time-range query compares instants rather than text, and refuses bounds without a timezone.

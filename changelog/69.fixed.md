The collector no longer drops data when a device splits one requested path across several gNMI updates. Before, each update for the same path overwrote the last, so only the final fragment survived and drift was computed against partial state with no error. Fragments are now merged: containers deep-merge and list entries are combined, with a re-sent identical entry kept once. Two fragments that disagree, such as two different values for one leaf, fail the collect with a parse error naming the leaf. `GnmiCollector` also rejects an empty or missing password at construction with `CollectorConfigError("password is required")`, as `GnmiExecutor` already did, instead of failing later with what looked like a per-device auth error.

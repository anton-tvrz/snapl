The executor reports a config that can't be rendered the same way from every entrypoint. An unknown use case, a template error, or template output that is not JSON now comes back as a failed result (`success=False`, error message set, nothing sent to the device) from `apply`, `rollback`, `dry_run` and `apply_batch`. Before this, `apply` and `rollback` raised on a render error while `apply_batch` reported it, and `dry_run` raised on an unknown use case, the one failure its result was built to report. The message now names the use case and the error type, e.g. `render failed for use case 'dcfabric': JSONDecodeError: Expecting value: line 1 column 1 (char 0)`. A deploy whose config can't be rendered now ends in `apply_failed` with that message, without the activity retrying a render that will fail every time.

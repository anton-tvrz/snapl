Fix workflow cancellation being unhandled in all three orchestrator workflows. They caught `temporalio.exceptions.CancelledError`, which is neither the `asyncio.CancelledError` raised in the workflow task nor the `ActivityError`/`ChildWorkflowError` a cancelled in-flight activity or child workflow raises. Cancellation is now detected with `temporalio.exceptions.is_cancelled_exception`, so a cancelled `DeployIntentWorkflow`/`ScanDriftWorkflow` terminates with `reason=CANCELLED` and a `ReconcileDevicesWorkflow` audits `WORKFLOW_CANCELLED` before re-raising. A cancelled scan no longer misreports cancelled devices as drift `ERROR`s, and a cancelled reconcile child is no longer miscounted as a deploy failure.

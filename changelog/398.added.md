`snapl remove <device>` previews removing config the device carries that intent never asked for (spec 013, #65). It scans the device through a new read-only `PlanRemoval` workflow and lists each delete it would issue, the drift paths each one answers, and what it refuses and why: the protected interfaces (`mgmt0`, `system0`, and their bindings) and routing policies. It checks the deletes against the executor's new guard, which admits only whole interfaces, extra addresses, BGP neighbours and network-instance bindings, and refuses everything when no protected set is configured. Nothing is written to the device. It exits 2 when there is something to remove and 0 when there is not; `--json` prints the plan.

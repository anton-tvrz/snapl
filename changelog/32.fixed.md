Live drift detection no longer reports 100% drift on a converged fabric. The orchestrator now translates raw SR Linux gNMI collect output into the structural-diff contract via a new `adapters.srlinux` module: it expands the collector's path-keyed, kebab-case `json_ietf` state (`/interface` → `{srl_nokia-interfaces:interface: [...]}`) into per-entity keys with flat snake_case fields (`/interface[name=ethernet-1/1]` → `{ip_address, prefix_length, enabled, mtu, description}`; BGP neighbors likewise). The `detect_drift` activity applies it before the Observer runs, and both the deploy verification step and ScanDrift now collect the entity container paths the adapter expands instead of rendered payload container names. Verified end-to-end against a live dcfabric SR Linux node: a converged device reports CLEAN and a real config change is flagged as exactly the drifted field.

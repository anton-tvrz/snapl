Temporal workflow history now survives a container restart. The dev server ran `temporal server start-dev` without `--db-filename`, which keeps history in memory — so any restart silently emptied the Web UI, taking the demo's durability receipt with it (found the hard way after a host reboot, when the UI showed zero workflows despite a validated closed-loop run five days earlier). History is now persisted to SQLite on a named `temporal_data` volume, like the rest of the stack's state. The volume is mounted on the image's own `/home/temporal` rather than a fresh `/data`: a volume mounted at a path the image does not already contain is created root-owned, and the unprivileged `temporal` user the server runs as cannot write to it, so the server dies at startup with `unable to create SQLite admin DB`. `demo.reset` still wipes it along with every other volume. Verified live — a completed `DeployIntent` and its full 65-event history, including all ten activity completions, are intact after `docker compose restart temporal`.

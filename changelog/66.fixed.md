`ReconcileDevicesWorkflow` no longer fails an entire run when the same device id appears twice — ids are deduped (order-preserving) before any child is dispatched, so duplicates can neither collide on the deterministic child id nor trip `ReconcileResult`'s count validator. Unexpected child-workflow failures are also classified correctly: the old `"not found"` substring test converted genuine failures (a gNMI "Requested element(s) not found", an audit-log error) into silent *skips*, so a reconcile could report success while a deploy had blown up. Classification now rests solely on the structured `DEVICE_NOT_FOUND` reason code that `DeployIntentWorkflow` returns.
